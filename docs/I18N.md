# Idiomas (español y maya yucateco) — merida-unificada

La plataforma se puede usar en **español** y en **maya yucateco (Maaya t'aan)**. El botón de idioma está en el encabezado; la elección se recuerda (`merida-demo:v1:idioma`) y se aplica a `<html lang>` (`es-MX` / `yua`).

> **Las traducciones al maya son preliminares** (generadas con un modelo de IA y un glosario). Deben revisarlas hablantes de maya (por ejemplo con INDEMAYA o la Academia de la Lengua Maya) antes de presentarlas como oficiales. Todo está en archivos JSON para que sea fácil corregirlas.

## Cómo funciona

- Librería: `i18next` + `react-i18next` (`src/i18n/`).
- **La clave de cada texto es el propio texto en español.** Si falta la traducción se ve el español (nunca una clave rara). Las pruebas corren en español y no cambian.
- Traducciones: `src/i18n/locales/yua/<módulo>.json` con la forma `{ "Texto en español": "Texto en maya" }`. Se cargan sólo si alguien elige maya.
- El aviso de traducción preliminar y voz experimental se mantiene en español como respaldo, sin afirmar que ya exista una revisión humana.
- El selector bloquea cambios simultáneos y muestra un aviso si no se puede cargar el idioma. Si falla la carga al iniciar, ofrece reintentar o continuar explícitamente en español.

## Cómo escribir textos en el código

```tsx
import { useTranslation } from "react-i18next";
const { t } = useTranslation();
<button>{t("Buscar")}</button>
<p>{t("Tienes {{n}} reportes", { n: total })}</p>      // interpolación
<input placeholder={t("Escribe con tus palabras")} aria-label={t("Buscar")} />
```

- Traduce **todo texto que lee la persona**: contenido, `aria-label`, `title`, `placeholder`, `alt`, mensajes de error y de validación, avisos, etiquetas de estado.
- **Constantes de módulo** (listas de etiquetas definidas fuera del componente): márcalas con `msg()` (devuelve el mismo texto) y tradúcelas al pintar:
  ```ts
  import { msg } from "@/i18n";
  const ITEMS = [{ id: "inicio", etiqueta: msg("Inicio") }];
  // …en el componente: {t(item.etiqueta)}
  ```
- Fuera de componentes (funciones puras, stores) importa `{ t } from "i18next"` y llámalo en el momento de usarlo, no al cargar el módulo.
- Una **clave es un literal** (`t("texto")`): el extractor no ve claves construidas dinámicamente. Para varias variantes usa varias llamadas literales; no uses plurales de i18next (escribe dos textos o redáctalo sin plural).
- Sin `t()`: folios (`DEMO-R-…`), siglas (911, CURP), nombres propios y de marca (Pekito, Mérida, Línea Mujer), datos oficiales del catálogo (nombres de trámites, requisitos…: son datos de una fuente oficial) y fechas/números (se formatean con `es-MX`).
- No concatenes frases traducidas: la gramática del maya no es la del español. Usa una sola clave con `{{marcadores}}`.

## Flujo para traducir

1. Escribe los textos con `t()`/`msg()` en español.
2. `npm run i18n:faltantes` lista lo que no tiene traducción (y valida los `{{marcadores}}`).
3. `npm run i18n:traducir` traduce lo que falta con OpenAI (`I18N_MODELO`, por defecto `gpt-6-sol`) y lo escribe en `src/i18n/locales/yua/`. **No sobrescribe** traducciones existentes (las ya revisadas), salvo `-- --forzar`.
4. Una persona hablante revisa y corrige los JSON.

## Asistente (Pekito) y voz en maya

- Al elegir maya, Pekito (texto y voz) y la búsqueda inteligente responden en maya yucateco; las instrucciones del servidor le piden usar un maya sencillo y, si no está seguro de un término, dejarlo en español. La información citada (dependencias, trámites) sigue en español de la fuente oficial y Pekito la explica en maya.
- **Limitación de la voz**: OpenAI Realtime no declara soporte oficial para maya yucateco. La transcripción se hace sin idioma fijo y la voz sintetizada puede sonar con acento del español. Es experimental: la interfaz ofrece el chat escrito como alternativa.
- Cambiar el idioma pausa las sesiones abiertas del asistente general y del acompañante. La siguiente interacción crea una sesión con el idioma elegido, sin trasladar mensajes entre asistentes ni renovar el consentimiento de bienestar.

## Validación

- `npm test`: regresiones de interfaz, contratos y lógica; incluye i18n y recuperación de errores del selector.
- `npm run test:e2e -- e2e/idioma.spec.ts`: cambio por teclado, persistencia, vuelta a español, accesibilidad automatizada, diseño responsivo y búsqueda con citas e idioma propagado (API simulada, sin llamadas externas).
- El extractor de claves no acredita cobertura de datos dinámicos ni calidad lingüística. Las pruebas automatizadas no sustituyen una revisión por hablantes ni una prueba de voz con habla maya auténtica.
